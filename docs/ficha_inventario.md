# Ficha de Inventario de la Automatización

| Campo | Detalle |
| :--- | :--- |
| **Nombre de la automatización** | Clasificador y Validador de Solicitudes de RRHH — Talento Andino S.A.S. |
| **Código / Repositorio** | `reto-automatizador-ia` (`github.com/droguelios/prueba-tecnica`) |
| **Proceso de negocio** | Recepción, clasificación, validación de saldos y enrutamiento de solicitudes de empleados (vacaciones, certificados laborales, incapacidades y actualización de datos). |
| **Tipo de solución** | Automatización híbrida: Pipeline en Python + SQLite + API REST (Nager.Date) + IA Generativa (Gemini API) orquestado con Power Automate para escritorio. |
| **Disparador (Trigger)** | Ejecución manual o programada desde **Power Automate para escritorio** (Opción A), el cual invoca el script `python -m src.main` y verifica la salida. |
| **Entradas (Inputs)** | 1. `data/empleados.csv` (maestro de nómina y saldo de vacaciones).<br>2. `data/solicitudes.json` (solicitudes recibidas por correo, chat y formulario).<br>3. API pública Nager.Date (`GET /api/v3/PublicHolidays/2026/CO`) con respaldo local `data/festivos_co_2026.json`.<br>4. Variable de entorno `GEMINI_API_KEY` (archivo `.env`). |
| **Salidas (Outputs)** | 1. `output/reporte_solicitudes.csv` (reporte consolidado para RRHH con estado y motivo de revisión).<br>2. `output/resultados.json` (respaldo estructurado del reporte).<br>3. `output/talento_andino.db` (base SQLite con datos limpios).<br>4. `output/consultas_sql.json` (indicadores SQL de nómina y solicitudes).<br>5. `output/metricas_ia.json` (exactitud de clasificación y errores detectados).<br>6. Log de ejecución generado por Power Automate (fecha, hora y resultado). |
| **Reglas de control humano (Human-in-the-Loop)** | Ninguna solicitud dudosa se aprueba automáticamente. Se marca `requiere_revision = si` con motivo cuando:<br>• La confianza de la IA es baja o falla la API.<br>• El empleado no existe en nómina.<br>• Es una solicitud de vacaciones sin fecha de inicio o fin.<br>• Los días hábiles solicitados superan el saldo disponible del empleado. |
| **Responsable (Owner)** | **Negocio:** Analista / Coordinador de Recursos Humanos (revisa excepciones y aprueba casos marcados).<br>**Técnico:** Automatizador de IA / TI (mantenimiento del código, llaves de API y monitoreo). |
| **Riesgos identificados y mitigación** | 1. **Exposición de datos personales (PII) a API externa:** Mitigado con enmascaramiento previo por regex (cédulas, celulares y correos) antes de llamar a la IA.<br>2. **Fuga de credenciales:** Mitigado con `.env` excluido en `.gitignore` y plantilla `.env.example`.<br>3. **Caída o límites de cuota de la API de IA (`429`/`503`):** Mitigado con manejo de excepciones que deriva el caso a revisión humana sin detener el flujo.<br>4. **Caída de la API de festivos:** Mitigado con *timeout*, reintentos y archivo de respaldo local (`festivos_co_2026.json`).<br>5. **Datos sucios en nómina (duplicados, vacíos, espacios):** Mitigado con limpieza automática y alertas en la ingesta a SQLite. |
| **Cómo se monitorea** | 1. **Log de ejecución (Power Automate):** Registra fecha, hora y resultado (`Éxito` / `Error`) en cada corrida y muestra alerta visual ante fallos.<br>2. **Validación de archivo de salida:** El flujo comprueba que `output/reporte_solicitudes.csv` exista y no esté vacío.<br>3. **Métricas de calidad de IA:** Revisión de `output/metricas_ia.json` para vigilar caídas de exactitud.<br>4. **Pruebas automatizadas:** Suite de 6 pruebas unitarias ejecutables con `pytest` ante cualquier cambio de reglas. |
